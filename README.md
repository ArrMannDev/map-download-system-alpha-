# DPS Map Download

DPS Map Download is a full-stack application that gates PDF map downloads behind email OTP verification. A visitor submits a name, email address, and map selection; the API stores the request in Supabase, emails a six-digit OTP, verifies it for five minutes, and then serves the selected PDF.

## Prerequisites

- Node.js compatible with Vite 8 (Node.js 20.19+ or 22.12+)
- A Supabase project with a `map_requests` table
- A Gmail account and app password

## Configuration

Create `client/.env`:

```dotenv
VITE_API_URL=http://localhost:5000
```

Create `server/.env` (ignored by Git):

```dotenv
SUPABASE_URL=https://YOUR_PROJECT.supabase.co
SUPABASE_SERVICE_ROLE_KEY=YOUR_SERVICE_ROLE_KEY
EMAIL_USER=your-account@gmail.com
EMAIL_PASS=your-gmail-app-password
```

The API requires the following inferred schema. No migration is currently included.

```sql
create table public.map_requests (
  id bigint generated by default as identity primary key,
  name text not null,
  email text not null,
  map_name text not null,
  otp text not null,
  otp_expires_at timestamptz not null,
  verified boolean not null default false
);
```

The service-role key bypasses Row Level Security. Keep it server-side only.

## Run locally

Start the API:

```powershell
cd server
npm install
npm run dev
```

In a second terminal, start the client:

```powershell
cd client
npm install
npm run dev
```

Open the URL printed by Vite (normally `http://localhost:5173`). The API port is currently hard-coded to `5000`.

Alternatively, run the Next.js client:

```powershell
cd next-client
Copy-Item .env.example .env.local
npm install
npm run dev
```

Open `http://localhost:3000`. The Next.js client reads the API origin from `NEXT_PUBLIC_API_URL`.

## PHP server alternative

An equivalent PHP implementation is available in [`php-server`](php-server/README.md). It exposes the same API contract and uses the same Supabase table and map PDFs, so the React client can switch between implementations by changing `VITE_API_URL`.

## API summary

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/` | Health/information response |
| `POST` | `/api/request-map` | Store a request and email an OTP |
| `POST` | `/api/verify-otp` | Verify the OTP |
| `GET` | `/api/download/:requestId` | Download the map after verification |
